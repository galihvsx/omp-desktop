# omp-desktop

Wails v2 (Go 1.25) + React 19 + TypeScript + Vite desktop app, scaffolded from the Wails React-TS template. Purpose: a desktop shell around the `omp` CLI coding agent (talks to `omp --mode rpc`). The RPC bridge (spawn / stream / stop `omp` sessions), session browsing and resume, cross-process session-conflict detection, embedded terminals, and git helpers are implemented; the UI is under active development.

Git repo on branch `main` — commits exist; ongoing development currently lives uncommitted in the working tree.

## Layout

- `main.go` — Wails entry; embeds `frontend/dist`, binds `App`. Window is **frameless** (`Frameless: true`, title "OMP Desktop", 1280x768) — the native frame is replaced by `frontend/src/components/title-bar.tsx`.
- `app.go` — `App` struct; every exported method here becomes a frontend-callable binding.
- `frontend/` — React TS app (Vite). `src/` is source; `dist/` is build output (embedded by Go — must exist before `go build`).
  - `src/components/ui/` — shadcn/ui v4 (React port: `@shadcn/react` over Base UI/Radix) primitives, managed via `frontend/components.json` (style `base-nova`, lucide icons, `@/` aliases).
  - `src/components/dashboard/` — app shell (sidebar layout via `components/dashboard/layout.tsx` + `app-sidebar.tsx`; `workspace/` holds workspace/session navigation). Pages live in `src/pages/` (chat, new-session, settings).
  - `src/components/workspace/` — conversation workspace UI (composer, messages, tool cards, permission dock, terminal panel, git summary and commit dialog).
  - `src/features/` — domain state (zustand stores and hooks) for omp sessions, terminals, workspaces, sidebar, and appearance.
  - `src/components/ai-elements/` — chat/message components from the Vercel ai-elements pattern (streamdown, `ai` SDK deps).
  - `src/hooks/` — `use-titlebar`, `use-navigate`, `use-mobile`.
  - Theming: next-themes-style `ThemeProvider` (`.dark` class) + design tokens as Tailwind v4 `@theme`/CSS variables in `src/style.css` (oklch palette, Geist font).
- `frontend/wailsjs/` — **generated** bindings (`go/` = Go method wrappers, `runtime/` = Wails runtime API). Never hand-edit; regenerated by `wails dev` / `wails generate module` when bound Go methods change.
- `build/` — platform packaging assets (appicon, darwin/windows manifests); `build/bin/` holds build output.
- App scripts and deps live in `frontend/package.json` (npm, `package-lock.json`). The root-level `package.json` / `pnpm-lock.yaml` stub from earlier skill tooling has been removed.
- `.zcode/skills/ai-elements/` (pinned in `skills-lock.json` from `vercel/ai-elements`) — read that SKILL.md before editing ai-elements / conversation components.

## Commands

- `wails dev` — live dev (Vite HMR + Go); browser dev server on http://localhost:34115 exposes Go methods to devtools.
- `wails build` — production binary into `build/bin/`.
- Frontend-only: `cd frontend && npm run dev | build | preview` (`build` = `tsc && vite build`, so typecheck runs there).
- `go test ./...`, `go vet ./...` — run from repo root; Go compiles require `frontend/dist` to exist (run `npm run build` in `frontend/` first on a clean checkout).

## Conventions / gotchas

- Wails CLI is required for dev/build (`wails doctor` to diagnose); plain `go run .` also needs `frontend/dist` present.
- Add backend functionality as exported methods on `App` (or new bound structs added to `Bind` in `main.go`), then let `wails dev` regenerate `frontend/wailsjs/go/...` and import the wrapper in React — do not call Go via ad-hoc strings.
- Frameless window: dragging/resizing goes through Wails runtime calls (`use-titlebar` hook) — don't add native-frame assumptions or OS chrome styling.
- Frontend has no lint or test setup yet; only typecheck via `tsc` in `npm run build`. Imports use the `@/` alias (mapped in `vite.config.ts` and `tsconfig.json`).
- New UI primitives go through the shadcn v4 CLI into `src/components/ui/` (see `components.json` aliases); don't hand-roll parallel component libraries. Colors/spacing come from the token variables in `src/style.css` — don't hardcode hex values in components.
- Development platform is Windows (WebView2); `build/windows/` holds the manifest.
- Prior iterations of this project (Electrobun, then Tauri 2) were discarded — don't reintroduce tooling from those stacks.

## Wireframe Prototype Rules (apply ONLY inside `wireframes/`)

`wireframes/` holds low-fidelity clickable prototypes (agilek/wireframer-skill). Constraints for anything generated or edited there:

- Strict grayscale/monochrome (black/white/grays); muted sketchy blue only for primary links; links underlined.
- `wired-elements` (CDN) for interactive UI; plain `<button class="btn-primary|btn-secondary">` (sketchy-border CSS) for primary/secondary actions — never `<wired-button>`.
- Icons: inline SVG from `react-doodle-icons` (pre-extracted in `wireframes/icons.js`, render via `di(name, size)`); NEVER emoji as icons.
- Typography: Google Font `Patrick Hand`; Major Third scale `.text-xs…​.text-xl` from the skill; never below 13px.
- Graph-paper background (`radial-gradient` dots), sketchy borders (`border-radius: 255px 15px 225px 15px / 15px 225px 15px 255px; background: white`).
- SPA without a router: `.screen` divs toggled by vanilla JS; realistic copy, no lorem ipsum.
